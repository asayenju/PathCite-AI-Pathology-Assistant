# PathCite frontend

Vue 3 + TypeScript + Tailwind v4 + shadcn-vue. Drag one of nine sample slides (one per tissue class) onto the stage and read the model's prediction.

> Research use only. Not a diagnosis.

## Run

Start the backend first (see `../backend/README.md`), then:

```
cd frontend
npm install
npm run dev
```

Open http://localhost:5173. In dev, Vite proxies `/api/*` to `http://localhost:8000` (prefix stripped), so the backend needs no CORS setup. To point at a hosted backend, set `VITE_API_BASE`.

## Scripts

```
npm run dev         # dev server
npm run build       # type-check and production build
npm run type-check
npm test            # unit tests (API client, class list, bundled samples)
```

## Notes

- Sample slides are in `public/samples/<CLASS>/` (one folder per tissue class, 8 slides each; `samples.json` lists them). The left column shows them as a folder tree. They are JPEG renderings from the NCT-CRC-HE-100K test split (Kather et al., CC-BY-4.0): 224x224 px at 0.5 µm/px, which is why the stage can draw a true 25 µm scale bar for them.
- Each folder holds the first 8 cached images of its class, unfiltered, so some slides are misread (in the model's weakest class, STR, only about 6 of 20 come out right). The folder name is the slide's true label; the reading shows "Matches" or "Differs from label". Treat the folders as a demo, not a measure of accuracy.
- Score ruler: the tick at 0.70 is the backend's default `UNCERTAIN_THRESHOLD`. The `uncertain` flag in the response decides the colour, so a different server setting still behaves correctly; only the tick position would be off.
- `src/lib/classes.ts` must keep the same order as `backend/app/classes.py` (a test checks this).
- shadcn-vue components in `src/components/ui/` were added with CLI v2.4.3: the latest CLI crashes on Node 20.
- Transcripts tab: drop or pick a diarized transcript JSON (Deepgram, AWS Transcribe, WhisperX, OpenAI diarized; up to 20 MB). It is posted to `/transcripts/import` and shown as a read-only summary. The client (`src/lib/transcripts.ts`) refuses empty, oversized and non-JSON files before uploading. The transcript lives only in memory (`composables/useTranscriptImport.ts`); nothing is written to web storage. Both tabs stay mounted, so switching keeps each view's state.
- Sample transcripts: `public/transcripts/<folder>/<id>.json`, listed in `public/transcripts/index.json` (generated by `backend/tests/fixtures/transcripts/generate.py`; don't edit by hand). They are synthetic, AI-written visits, not real patients. Click one or drag it onto the drop zone (MIME `application/x-pathcite-transcript`) and it is fetched and imported through the same `readFile` path as an upload, replacing the current transcript. If the manifest can't load, the sample panel is hidden.
- Not built yet: Azure storage for slides, auth, batch upload, dark mode, a real claim checker (claims are triaged by Jev but not fact-checked).

## Transcript review (Jev triage)

> Triage by Jev (TypeSafe). Claims are not fact-checked yet. Doctor turns are sent to TypeSafe. Research use only, not a diagnosis.

See `docs/PRD-jev-triage.md`. There is no BAA with TypeSafe, so only review synthetic or de-identified transcripts.

- **Flow:** import a transcript (any bundled sample or an upload), check the speaker roles (there is no confirm step; at least one speaker must be the doctor, otherwise the button is disabled with a note), then press **Review with agent**. `lib/jevReviewSource.ts` posts only the doctor turns (text and word confidences) to `/api/triage` and reads its NDJSON stream; the backend needs `JEV_KEY` in the root `.env`, or the header shows the `triage_unavailable` message. The page scrolls to the review and the doctor turns are triaged one at a time (a steady "Reviewing…" pill on the current turn, which the scroll container follows unless you scrolled in the last few seconds). While reviewing, the transcript and the margin share one scroll container (`TranscriptReviewLayout`).
- **Paced reveal:** Jev answers every turn within a second, so `lib/pacedReviewSource.ts` paces the display (Jev itself is still called at full speed). It reads the stream eagerly and holds each `turn_done` until the turn has been on screen for its dwell: a turn with n cards gets max(900 ms, its animations + a 400 ms reading pause), where the animations are a 300 ms highlight fade + 120 ms × (n − 1) card stagger + a 200 ms card slide; a turn with only skips gets 350 ms. A 15 s cap over the doctor turns can cut the reading pause but never the animations (quiet turns never drop below the 180 ms marker transition). It never adds latency beyond the dwell or reorders events; `error` and `done` wait only for the open turn; abort stops it at once. Highlights fade in once, cards slide up 6 px on their inner element (so `layoutCards` is untouched), and the marker fades between turns. The timings live in `lib/reviewMotion.ts` and reach the CSS as custom properties. With `prefers-reduced-motion` there is no pacing (`turnMs: 0`) and no animation.
- **What each span becomes:**
  - **Small talk** is skipped: no highlight, no card, only counted.
  - **Claim:** hematoxylin-blue highlight (`--color-hema`) and a "Claim" card. The claim goes to the claim checker (`lib/claimChecker.ts`, a stub), so the card says "Checking…" (a polite live region) and then "Not fact-checked yet (the checker isn't built yet)", or the error.
  - **Possible transcription error:** dashed underline with a "?" icon and a card asking "Is this correct?". **Yes** turns it into what Jev thought apart from the transcription doubt: a claim (checked as above) or "Not a claim" (resolved). **No** opens "What was said?"; **Submit** (disabled while blank) sends the typed text to `/api/triage/span` with up to two earlier doctor turns, showing "Checking your correction…". A claim becomes a Claim card "Checked as: “…”"; small talk resolves the card as "Not a claim" with the correction. If that call fails the card shows the error and can be answered again. The transcript text itself is never edited.
  - An answered card that resolves stays visible, collapsed, while it is the selected card; afterwards it hides like any resolved card (Show resolved brings it back).
- **Actions:** every card can be resolved, reopened, or disagreed with (optional reason: "this isn't a claim" is useful eval data). Triage cards have no reply box (`canReply` is false: Jev labels spans and can't answer questions). After No, focus moves to the input; after Yes or a successful Submit it stays on the card. The verdict is always given by icon and text (screen readers hear "(claim)" or "(possible transcription error)" after the span), never by colour alone, and animations respect `prefers-reduced-motion`.
- **Header:** the Jev label, status, counts of claims, open transcription checks and skipped spans, Previous/Next (across claims and open transcription checks), Show resolved, Stop and Export.
- **Invalidation:** Clear, loading another file or sample, and changing a role discard the review (the stream and any check or correction are aborted). A role change asks first if there are comments (cancel keeps the old role). "Restart review" discards and starts again.
- **Cards and scrolling:** like Google Docs, unselected cards are compact (verdict, quote, check state or question); the selected card expands smoothly to show its controls and snaps level with its highlight. Clicking a highlight smoothly scrolls to its card; clicking a card (or Previous/Next) scrolls to its highlight. New cards stay invisible until they are laid out at their highlight, then fade in once.
- **Mock (test data only):** `src/mocks/review/` holds hand-written fact-check comments for three samples, with `mockReviewSource` and `mockClarify`. The app no longer uses them; tests do. The fact-check verdicts (inaccurate ✕, incomplete +, accurate ✓) and the reply thread still render for any source that sends them.
- **Contract:** the UI only depends on `src/types.ts`. A `ReviewSource` is `(turns: RoledTurn[], signal) => AsyncIterable<ReviewEvent>` (`turn_started`, `comment`, `span_skipped`, `turn_done`, `done`, `error`); it must stop when `signal` aborts. Jev comments carry `triage` (`kind`, `base_kind`, `p_claim`, `p_asr`) and arrive with `start`/`end` set; their id is `<turn_id>:<start>`. A `ClaimChecker` checks claims and a `SpanTriager` triages corrections; both are injectable in `useTranscriptReview`.
- **State and DOM contract:** `composables/useTranscriptReview.ts` holds the run (`idle | running | done | stopped | error`), each comment's status (`open | resolved | disagreed`), disagree reason, thread and triage state, in memory only. `TranscriptView` marks each highlight with `data-anchor-for="<id>"` and `aria-describedby="comment-<id>"`, and `ReviewMargin` positions the card with `id="comment-<id>"` against that anchor. Ids can contain `:`, so select them with attribute selectors or `getElementById`, not `#id`.
- **Export:** **Export review** downloads `review-<sample-id or "transcript">-<YYYYMMDD>.json` in the browser (nothing is uploaded). It has `notice` (the Jev label plus the research-use disclaimer), `source: "jev"`, `sample_id`, `exported_at`, `model` (e.g. `jev-1.14.0`) and `comments` (id, turn id, quote, verdict, status, `disagree_reason`, thread, `kind`, `p_claim`, `p_asr`, `confirmed`, `correction`, `checked_as`, `check_status`). The transcript text is not included, apart from the quotes and corrections.

# PathCite frontend

Vue 3 + TypeScript + Tailwind v4 + shadcn-vue. Drag one of nine sample slides (one per tissue class) onto the stage and read the model's prediction.

> Research use only. Not a diagnosis.

## Run

Start the backend first (see `../backend/README.md`), then:

```
cd frontend
npm install
npm run dev
```

Open http://localhost:5173. In dev, Vite proxies `/api/*` to `http://localhost:8000` (prefix stripped), so the backend needs no CORS setup. To point at a hosted backend, set `VITE_API_BASE`.

## Scripts

```
npm run dev         # dev server
npm run build       # type-check and production build
npm run type-check
npm test            # unit tests (API client, class list, bundled samples)
```

## Notes

- Sample slides are in `public/samples/<CLASS>/` (one folder per tissue class, 8 slides each; `samples.json` lists them). The left column shows them as a folder tree. They are JPEG renderings from the NCT-CRC-HE-100K test split (Kather et al., CC-BY-4.0): 224x224 px at 0.5 µm/px, which is why the stage can draw a true 25 µm scale bar for them.
- Each folder holds the first 8 cached images of its class, unfiltered, so some slides are misread (in the model's weakest class, STR, only about 6 of 20 come out right). The folder name is the slide's true label; the reading shows "Matches" or "Differs from label". Treat the folders as a demo, not a measure of accuracy.
- Score ruler: the tick at 0.70 is the backend's default `UNCERTAIN_THRESHOLD`. The `uncertain` flag in the response decides the colour, so a different server setting still behaves correctly; only the tick position would be off.
- `src/lib/classes.ts` must keep the same order as `backend/app/classes.py` (a test checks this).
- shadcn-vue components in `src/components/ui/` were added with CLI v2.4.3: the latest CLI crashes on Node 20.
- Transcripts tab: drop or pick a diarized transcript JSON (Deepgram, AWS Transcribe, WhisperX, OpenAI diarized; up to 20 MB). It is posted to `/transcripts/import` and shown as a read-only summary. The client (`src/lib/transcripts.ts`) refuses empty, oversized and non-JSON files before uploading. The transcript lives only in memory (`composables/useTranscriptImport.ts`); nothing is written to web storage. Both tabs stay mounted, so switching keeps each view's state.
- Sample transcripts: `public/transcripts/<folder>/<id>.json`, listed in `public/transcripts/index.json` (generated by `backend/tests/fixtures/transcripts/generate.py`; don't edit by hand). They are synthetic, AI-written visits, not real patients. Click one or drag it onto the drop zone (MIME `application/x-pathcite-transcript`) and it is fetched and imported through the same `readFile` path as an upload, replacing the current transcript. If the manifest can't load, the sample panel is hidden.
- Not built yet: Azure storage for slides, auth, batch upload, dark mode, a real review agent.

## Transcript review (demo)

> Demo review: hand-written mock, not an AI agent. Research use only, not a diagnosis.

- **Flow:** import a transcript, check the speaker roles (there is no confirm step; at least one speaker must be the doctor), then press **Review with agent**. The page scrolls to the review and the doctor turns are reviewed one at a time (a steady "Reviewing…" pill on the current turn, which the scroll container follows unless you scrolled in the last few seconds). Spans are highlighted as they arrive (inaccurate ✕, incomplete +, accurate ✓ underline with no card), and each issue gets a comment card in the right margin, lined up with its highlight (below `lg` the cards are a list). Cards can be resolved, reopened, disagreed with (optional reason) and replied to. The header has counts, Previous/Next issue, Show resolved, Stop and Export. While reviewing, the transcript and the margin share one scroll container (`TranscriptReviewLayout`); otherwise the transcript view is unchanged.
- **Availability:** only the three mocked samples (`crc_adenocarcinoma`, `breast_idc`, `melanoma`) can be reviewed. For other samples and for uploads the button is disabled with a note saying why.
- **Invalidation:** Clear, loading another file or sample, and changing a role discard the review. A role change asks first if there are comments (cancel keeps the old role). "Restart review" discards and starts again.
- **Cards and scrolling:** like Google Docs, unselected cards are compact (verdict, quote, issue); the selected card expands smoothly to show the suggestion, source, actions and reply box, and snaps level with its highlight. Clicking a highlight smoothly scrolls to its card; clicking a card (or Previous/Next) scrolls to its highlight. New cards stay invisible until they are laid out at their highlight, then fade in once, so nothing flashes at the top of the margin.
- **Mock source:** `src/mocks/review/` holds hand-written comments per sample (`crcAdenocarcinoma.ts`, `breastIdc.ts`, `melanoma.ts`, keyed in `reviews.ts`). `mockReviewSource(sampleId)` streams them with a 900 ms delay per doctor turn, and `mockClarify` answers replies with canned text after 800 ms. The comments were not reviewed by a pathologist.
- **Plugging in a real agent:** the UI only depends on the contract in `src/types.ts`. A `ReviewSource` is `(turns: RoledTurn[], signal) => AsyncIterable<ReviewEvent>` (`turn_started`, `comment`, `turn_done`, `done`, `error`), and a `ClarifySource` is `(comment, question, signal) => Promise<string>`. Comments are anchored by `turn_id` + `quote` (first exact match in the turn text; no match makes an orphan card). To swap the mock out, pass a different source to `useTranscriptReview` / `start()` in `TranscriptDrop.vue`, e.g. one that reads an SSE endpoint. It must stop when `signal` aborts.
- **State and DOM contract:** `composables/useTranscriptReview.ts` holds the run (`idle | running | done | stopped | error`) and each comment's status (`open | resolved | disagreed`), disagree reason and thread, in memory only. `TranscriptView` marks each highlight with `data-anchor-for="<id>"` and `aria-describedby="comment-<id>"`, and `ReviewMargin` positions the card with `id="comment-<id>"` against that anchor.
- **Export:** **Export review** downloads `review-<sample-id>-<YYYYMMDD>.json` in the browser (nothing is uploaded). It has `notice`, `source: "mock"`, `sample_id`, `exported_at` and `comments` (id, turn id, quote, verdict, issue, suggestion, source, status, `disagree_reason`, thread). The transcript text is not included, apart from the quotes.
